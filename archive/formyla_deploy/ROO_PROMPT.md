## Контекст бага

Пользователь просит задачу с доп. построением (например, incircle). Модель корректно генерирует aux-план, движок его строит, но в UI aux-построение не появляется — показывается только base-чертёж, без вписанной окружности и биссектрис.

Причины (уже найдены и исправлены в приложенном патче):

1. В `figures_generator.py`, в функции `_run_solver_aux_job`, стадия `visual_check` роняла aux на любой ошибке, включая косметические `LABEL_COLLISION` / `TICK_OVERLAP`. Плюс проглатывала exception и не писала `_record_stage` — в БД не оставалось следов.
2. В `schema.json` enum типов не покрывал 8 типов, реально поддерживаемых движком (`inscribed_polygon`, `midpoint_mark`, `parallel_line`, `parallel_mark`, `perpendicular_mark`, `point_on_circle`, `reflect_point`, `rotate_point`) — планы с ними отбраковывались ДО движка.
3. В `engine.py`, в обработчике `circle_center_radius`, при отсутствии распознанного ключа радиус молча ставился = 1.0. На incircle это давало вырожденную окружность и ложный `INCIDENCE_VIOLATED`.

## Что лежит в `formyla_deploy/`

- `fixed/figures_generator.py` — целевой файл для `routes/figures_generator.py` (или где у меня блюпринт figures).
- `fixed/engine.py` — целевой файл для `geometric_engine/engine.py`.
- `fixed/schema.json` — целевой файл для `data/figures/schema.json` (пути уточни поиском).
- `diffs/*.diff` — те же правки в формате unified diff, для ревью.
- `tests/test_engine_incircle.py` и `tests/test_engine_extras.py` — тесты на stdlib, должны пройти после патча.
- `docs/AUDIT_REPORT.md` — полный отчёт по правкам.

## Что от тебя нужно (по шагам)

1. **Найти реальные пути** трёх целевых файлов в моём репозитории (`figures_generator.py`, `engine.py`, `schema.json`). Используй поиск по имени и по характерным сигнатурам (`_run_solver_aux_job`, `class GeometricEngine`, `"circle_center_radius"` в enum). Не полагайся на догадки о структуре папок.

2. **Сверить версии.** Для каждого целевого файла:
   - Открой мой текущий файл в репо и `formyla_deploy/fixed/<файл>`.
   - Покажи мне summary изменений: какие блоки добавляются, какие правятся, какие функции затрагиваются.
   - Проверь, нет ли в моём репо более свежих правок, которые могли уйти в те же строки. Если нашёл конфликт — покажи его, не перезаписывай молча.

3. **Применить патч** только после моего подтверждения:
   - Для `figures_generator.py` и `engine.py` предпочтителен точечный merge (перенести именно изменённые блоки), а не полная замена файла — у меня могут быть локальные правки в других местах.
   - Для `schema.json` можно заменить целиком, если diff покажет, что отличаются только правленые куски.
   - Все правки — в новой ветке, например `fix/aux-dropped-visual-check`, отдельными коммитами по одному файлу.

4. **Прогнать тесты локально** прямо в песочнице Roo:
   ```
   cd /path/to/repo
   PYTHONPATH=. python tests/test_engine_incircle.py
   PYTHONPATH=. python tests/test_engine_extras.py
   ```
   Оба должны напечатать несколько строк `... OK`. Если тесты падают — не создавай PR, покажи мне stacktrace.

5. **Дать мне готовый PR-текст** на русском: короткое описание бага, список изменений по файлам, чек-лист «что проверить в проде», ссылку на `docs/AUDIT_REPORT.md`.

6. **Не трогать** файлы вне списка: `services/visual_audit.py`, `services/aux_compiler.py` и прочие сервисы могут содержать смежные баги, но по ним у меня нет проверенных правок. Если увидишь, что мой патч ссылается на функции из этих сервисов (`audit_rendered_figure`, `_recognize_incircle`) — только пометь это в PR-описании как «требует отдельного прохода», не редактируй.
