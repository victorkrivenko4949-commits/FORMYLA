# Отчёт: рисунки в методах олимпиадной математики

## Краткий вывод

**Из 105 методов только метод F1 имеет SVG-чертежи.**  
Все остальные 104 метода не содержат никаких рисунков — ни в каталоге, ни в файловой системе, ни в механизме инжекции.

---

## 1. Как рисунки подключаются к методам

Единственный механизм — сервис [`services/geometry_drawings.py`](services/geometry_drawings.py):

- Сканирует директорию [`static/img/vsosh9_geometry/`](static/img/vsosh9_geometry/)
- Ищет файлы по шаблону: `F{code}_{family}.{task}_{nr}.svg`
- Срабатывает **только** если `method_code` начинается с `F`
- После каждого `<h4>Задача N.M</h4>` в рендереном HTML вставляет `<figure>` с одним или двумя `<img>`

Остальные методы (A, B, C, D, E, G, H, I, J...) не имеют механизма подгрузки изображений.

## 2. Поиск в `methods_catalog_105.json`

Каталог [`data/olympiads/methods_catalog_105.json`](data/olympiads/methods_catalog_105.json) проверен — ни в одном из 105 методов нет:
- `![](...)` — markdown-изображений
- `<img` — HTML-тегов
- `.svg`, `.png`, `.jpg` — ссылок на файлы

Для справки, в проекте есть ещё 3 системы изображений, но они **не относятся к методам**:

1. [`problem_images.py`](problem_images.py) — IMAGE_MAP для **probnik-задач** (105 записей, пути вида `img/olympiads/...` или `problem_images/...`)
2. [`services/figures_manifest.py`](services/figures_manifest.py) — MANIFEST.json (205 записей) для **probnik-фигур**
3. [`services/solution_figures.py`](services/solution_figures.py) — `solution_figures_index.json` для **страниц решений**
