# Промпт для эксперта (Perplexity / Claude / GPT)

Ты — эксперт по геометрическим движкам и планиметрии. Разберись в системе и
почини ошибки.

## Система

ФОРМУЛА — платформа автоматической генерации чертежей по тексту планиметрической
задачи. Конвейер (режим `solver_aux`):

1. `base_planner` (Gemini) строит ИСХОДНЫЙ чертёж по условию.
2. `solver` (DeepSeek v4-pro) решает задачу и возвращает JSON, где
   `aux_constructions` = список доп. построений (op + точки + quote из решения).
3. `compile_solver_aux` (детерминированный компилятор, `services/aux_compiler.py`)
   переводит `aux_constructions` в план движка через закрытый словарь
   `services/aux_ops.py`.
4. `merge_base_aux` склеивает исходный и aux-план.
5. `geometric_engine` исполняет и рендерит SVG (пунктир = доп. построение).

Ключевой принцип: **всё, что продиктовал solver, должно быть нарисовано без
потерь.**

## Что в папке

- `code/` — исходники (все ключевые файлы конвейера и движка).

## Ошибки, которые нужно починить

1. **job_5427 — окружность «не там».** Вписанная окружность строится через
   `geom.incircle_touch_point(a, b, c)`, где ПЕРВЫЙ аргумент — противоположная
   вершина, а (b, c) — концы стороны касания. Если порядок аргументов неверный,
   точка касания ложится на другую сторону, и окружность/радиус уезжают.
   Проверь `incircle_touch` в `code/geometric_engine__engine.py` и
   `code/services__aux_compiler.py`.

2. **Точки касания не совпадают с равными отрезками.** В исходном плане точки
   касания иногда заданы как `point_on_segment` с произвольным `ratio`, из-за
   чего равенства касательных численно не выполняются. Нужен нативный
   `incircle_touch`.

3. **Потеря новых точек (`UNRESOLVED_POINT`).** DeepSeek пишет «точку D»,
   «основание K», «в точке E» без заполнения поля `id`; компилятор должен
   извлекать имя точки из `quote`, иначе следующий шаг падает.

4. **`line_intersection` с будущей точкой.** DeepSeek шлёт
   `points:[M, E, A, B]`, где E — результат пересечения, а первая «прямая» —
   уже построенная параллель через M. Компилятор должен резолвить её из реестра
   параллельных линий.

5. **`line_extension` с равенством длины («AD = AM»).** Это точка на луче за A
   на расстоянии |AM|, а не центральная симметрия (где AD = AB). Нужен примитив
   `point_on_ray(origin, away_from, length_from)`.

6. **Служебные подписи.** Точки с внутренним id `aux_*` не должны подписываться
   этим id — только настоящие геометрические имена.
