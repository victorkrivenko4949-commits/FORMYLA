## 2. Failure Mode Analysis (Анализ точек отказа)

### 2.1 Точка отказа: Кеширование байт-кода Python

**Проблема:**  
Python компилирует `.py` файлы в байт-код `.pyc` и сохраняет в `__pycache__/`. При импорте модуля Python проверяет:
1. Существует ли `.pyc` файл?
2. Совпадает ли timestamp `.pyc` с `.py`?

Если `.pyc` существует и timestamp совпадает, Python загружает байт-код **без чтения исходного `.py` файла**.

**Почему возникла проблема:**  
Скрипт [`fix_see_figure.py`](fix_see_figure.py) изменил [`olympiads.py`](olympiads.py), но Python продолжал использовать старый байт-код из `__pycache__/olympiads.cpython-313.pyc`.

**Решение:**  
```cmd
rmdir /S /Q __pycache__
```

**Статус:** ✅ Устранено

---

### 2.2 Точка отказа: Неполный поиск паттернов

**Проблема:**  
Первый скрипт [`fix_see_figure.py`](fix_see_figure.py) искал только:
```python
content.replace('(см. рисунок)', '')  # только со скобками
```

Но в файлах были вхождения **БЕЗ скобок**:
- `olympiads.py` строка 83: `"...4 клетки (две пары) и 4 треугольника (см. рисунок)"`
- `problems.py`: 2 вхождения без скобок

**Почему пропустили:**  
Анализ показал, что в большинстве случаев фраза была в скобках `(см. рисунок)`, поэтому первый скрипт искал только этот вариант.

**Решение:**  
Создан улучшенный скрипт [`fix_all_see_figure.py`](fix_all_see_figure.py), который обрабатывает 7 паттернов:
- Со скобками: `(см. рисунок)`, `(см.\nрисунок)`, `(см.рисунок)`, `( см. рисунок )`
- Без скобок: `см. рисунок`, `см.\nрисунок`, `см.рисунок`

**Статус:** ✅ Устранено
