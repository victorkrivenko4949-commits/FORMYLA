# Чистка каталога олимпиадных задач (olymp_catalog_fix)

Пайплайн из 22 этапов для чистки `data/olymp_catalog/` (4624 задачи,
13 файлов, 12 именованных олимпиад).
Детерминированная чистка (этапы 1–4, 8–10, 12–17) → правки DeepSeek с математической
сверкой deepseek-reasoner → поиск официальных источников (этапы 18–21) → финальная
валидация и отчёт (этап 22).

## Атрибуция: год, вариант, дыры

- **Год из сезона**: имя файла `...otbor-24-25.pdf` → 2025 (год финала сезона) —
  так же, как в базе (отборочный 23-24 лежит под 2024).
- **Поле `variant`** (необязательная строка): извлекается из заголовков блоков PDF
  («Вариант N», «Билет N», «в. N», «Вариант N (день M)») и из имён файлов.
  Дыры в нумерации считаются по ключу `(year, round, grade, variant)`.
  Существующим задачам без варианта он проставляется только после
  ПОДТВЕРЖДЕНИЯ: нечёткое совпадение текста с блоком PDF (нормализованная
  вложенность ≥ 0.9) даёт лишь ПРЕДЛОЖЕНИЕ; окончательная атрибуция требует
  raw-схожесть полного текста ≥ 0.9 (без удаления математики), совпадения
  ответов (структурно, знаки и \Gamma ≠ \gamma сохраняются) и гейта
  эквивалентности deepseek-reasoner. Любой конфликт — `needs_review`,
  поле `variant` не ставится. Заголовок блока приоритетнее поля variant,
  которое модель вернула в задаче (расхождение — только заметка в `qa`).

## Как работает поиск источников (этапы 18, 20, 21)

1. **Индекс официальных PDF** (`scripts/olymp_source_index.py`) — первый источник кандидатов:
   - шаг 1: существующие `source` из базы (id олимпиады, год, класс, этап, вариант — из имён файлов);
   - шаг 2: обход **родных сайтов олимпиад**: `mmo.mccme.ru` (ММО),
     `olympiads.mccme.ru/matprazdnik` (Матпраздник), `matol.ru` (Эйлер),
     `olymp.mipt.ru` + `tasks.olimpiada.ru/395` (Физтех), `tasks.olimpiada.ru/389` +
     сайт Курчатова, `turgor.ru/problems` (Турнир городов — один PDF на несколько классов,
     grades список), `olymp.hse.ru` (Высшая проба), `olimpiada.spbu.ru` (СПбГУ),
     `pvg.mk.ru` (ПВГ), `formulo.org` (Формула Единства), `olymp.msu.ru` (Ломоносов),
     `vos.olimpiada.ru` (ВсОШ заключительный).
     Схема обходчика: страница архива → ссылки на PDF →
     `{url, year, grade(s), round_key, kind, variant}`; год/этап берутся
     из имени файла и контекста секции страницы (заголовки перед ссылкой);
     служебные PDF (регистрация/положение/регламент) отфильтровываются.
   Кэш: `work/source_index/<slug>.json` (TTL неделя, `OLYMP_INDEX_TTL_HOURS`;
   `--rebuild-index` — перестроить; `OLYMP_INDEX_CRAWL=0` — без обхода сайта).
2. **Gemini через OdiRouter** — только если в индексе ничего не нашлось:
   grounding с `stream=True` (чанки идут сразу — nginx не рвёт соединение по 60 с),
   `web_search_options.search_context_size="low"`, компактный промт (≤ 400 токенов),
   таймаут клиента 55 с. Ручное управление: `ODIROUTER_WEB_SEARCH=0/1`, `ODIROUTER_MODEL=<id>`.
3. Найденный PDF скачивается (браузерный User-Agent, редиректы, принимаются
   `application/pdf` и `octet-stream`; HTTP-код и Content-Type логируются),
   страницы блока нужного класса/варианта ищутся по заголовкам («Вариант N»,
   «Билет N», «N класс»), DeepSeek-chat извлекает задачу (этап 20) или весь блок
   варианта (этап 21), DeepSeek-reasoner проверяет совпадение условия и ответа.
4. Все попытки логируются в `work/search_log.jsonl`: запрос, источник (index|gemini),
   URL, статус скачивания, результат проверки — видно, почему отказ.

## Этап 21: заполнение дыр

- Дыры — по ключу `(year, round, grade, variant)`; `--limit` — бюджет в ВАРИАНТАХ:
  безвариантная группа тратит 1 на первый найденный вариант, каждый следующий
  вариант в ней — ещё 1; не вместившийся вариант откладывается в очередь
  (`stage21_pending` в чекпоинте) с дырой «не обработано: --limit (вариант)»
  и будет обработан при следующем запуске без лимита. Прогон по одной
  олимпиаде: `--slug <slug>`.
- **Очередь дыр** переживает перезапуск: сохраняется в чекпоинте ДО обработки
  группы (хвосты вариантов, в т.ч. виртуальные — вариантов без записей
  в каталоге). Отсутствие номера в новом кандидате не закрывает дыру:
  пара (вариант, номер) остаётся в ожидании, пока не закрыта фактически.
- Вариант импортируется **целиком**: все задачи с условием, ответом, решением,
  баллами (в `qa.notes`). Условия и решения могут лежать в разных PDF —
  они объединяются по номеру задачи.
- **Дубль по тексту** (схожесть ≥ 0.9 с задачами того же года/класса) не добавляется,
  а обогащает существующую запись: `variant`, `source`, официальное решение
  (при статусах `gemini_solved`/`AI_*` → `official_found`).
- Диапазонные дыры считаются только по записям каталога, НЕ импортированным
  этапом 21 (`qa.stage21.imported`): импорт задаёт нумерацию блока PDF и не
  создаёт фантомных ожиданий. Запись, получившая вариант, покидает свою
  группу, но её номер по-прежнему закрывает диапазонные дыры.
- Отчёт по каждой олимпиаде: найдено PDF, импортировано вариантов/задач, обогащено
  существующих, пропущено дублей, неподтверждённых атрибуций (`needs_review`),
  не обработано из-за `--limit`, остаток дыр со списком (year, round, grade,
  variant, num) и причиной (нет PDF / не скачан / вариант не найден в документе /
  не найдена в новом кандидате / не извлечена). При нулевых дырах отчёт НЕ
  заявляет полного закрытия, если есть needs_review или необработанные группы;
  полное закрытие подтверждайте независимой сверкой с официальными PDF
  (валидация JSON/UID полноту не доказывает).
- Сверка deepseek-reasoner: решение должно приводить к ответу (явный вердикт
  `match`); неопределённый вердикт или отсутствие reasoner — задача
  не импортируется и не перезаписывает существующие данные.

## Ключи

```bash
export ODIROUTER_API_KEY=...    # OdiRouter (Gemini 3.6 Flash) — только поиск
export DEEPSEEK_API_KEY=...     # DeepSeek — чистка текста и математическая сверка
# необязательно:
export ODIROUTER_BASE_URL=https://odirouter.ai/api/v1
export ODIROUTER_MODEL=...      # id модели вручную (тогда /models не запрашивается)
export ODIROUTER_WEB_SEARCH=1   # 0 — выключить grounding, 1 — включить без пробы
```

При старте скрипт сам проверяет `GET /models` у OdiRouter (если путь другой —
подскажет; модель можно задать вручную через `ODIROUTER_MODEL`), находит модель
по подстроке `gemini-3.6-flash` (нет — напечатает список gemini-* и остановится)
и пробует web-search потоковым запросом (обходит 504-таймаут nginx); без него
Gemini возвращает URL-кандидатов, а скрипт сам скачивает документы (PDF через
pdfplumber/pypdf) и проверяет, что условие реально содержится в документе
(нечёткое совпадение ≥ 0.8).

## Установка

```bash
pip install -r requirements-olympfix.txt
```

## Порядок запуска (рекомендованный)

```bash
# 1. Смотрим, что изменится (API не вызывается, данные не трогаются)
python scripts/olymp_catalog_fix.py --stages 1-17 --dry-run

# 2. Чистим (результат — в data/olymp_catalog_fixed/, отчёт — в reports/)
python scripts/olymp_catalog_fix.py --stages 1-17

# 3. Поиск официальных решений и заполнение дыр (Gemini + DeepSeek)
python scripts/olymp_catalog_fix.py --stages 18-22 --slug phystech

# 4. После просмотра отчёта — применить к data/olymp_catalog/
#    (бэкап оригинала создаётся в backup/olymp_catalog_<дата>/)
python scripts/olymp_catalog_fix.py --apply
```

## Полезные флаги

| Флаг | Назначение |
|---|---|
| `--stages 1,3,5-9` или `all` | выбор этапов |
| `--slug phystech` | одна олимпиада |
| `--limit N` | ограничить объём (на этапе 21 — бюджет в вариантах, см. выше) |
| `--dry-run` | без изменений данных и чекпоинта |
| `--workers 8` | параллельные потоки |
| `--resume` | продолжить с чекпоинта `work/checkpoint.json` |
| `--apply` | скопировать результат в `data/olymp_catalog/` с бэкапом |
| `--source <dir>` | каталог-источник (по умолчанию: `data/olymp_catalog_fixed`, если уже существует) |

## Что получается на выходе

- `data/olymp_catalog_fixed/` — исправленный каталог (оригинал не трогается до `--apply`);
- `reports/olymp_catalog_fix.md` — сводный отчёт по этапам, needs_review, токены;
- `reports/olymp_catalog_fix_diff.jsonl` — журнал изменений (uid, этап, поле, было, стало);
- `work/checkpoint.json` — чекпоинт идемпотентности (uid + этап + хеш входа);
- в каждую запись добавляется только поле `qa` (что исправлено, каким этапом, какой моделью,
  старые значения); при подтверждённой атрибуции и импорте дыр этап 21 также
  проставляет `variant` и добавляет новые записи задач из официальных PDF.

## Принципы безопасности

- Ничего не генерируется: официального решения нет — задача помечается (`needs_review`,
  `official_not_found`), а не сочиняется.
- LaTeX-инвариант: правки DeepSeek-chat сверяются deepseek-reasoner-ом; при сомнении —
  откат и пометка `needs_review`.
- Только официальные домены (olymp.mipt.ru, tasks.olimpiada.ru, rsr-olymp.ru,
  olympiads.mccme.ru, turgor.ru, vos.olimpiada.ru, olymp.msu.ru, olymp.hse.ru,
  kurchatov-olymp.ru, formulo.org, matol.ru, mathus.ru); reshimvse/otvet.mail.ru и
  подобные игнорируются.
- Конфликт ответов не разрешается автоматически: оба варианта пишутся в `qa`
  с пометкой `answer_conflict`.
- Повторный запуск не портит уже исправленное: чекпоинт по uid+этап с хешем входа,
  атомарная запись через временный файл.
