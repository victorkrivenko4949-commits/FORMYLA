# 🔍 Система поиска оригинальных авторских решений

## Описание

Автоматическая система для замены AI-генерированных решений олимпиадных задач на оригинальные авторские решения из официальных источников с идеальным LaTeX форматированием.

## Проблема

- ❌ LLM генерирует решения сам → получаются длинные, путаные, часто неверные
- ❌ Олимпиадная математика требует коротких изящных решений
- ❌ Нужны оригинальные авторские решения из официальных источников

## Решение

Двухэтапный процесс:
1. **Поиск оригинала** - LLM ищет точное решение в своей базе знаний (problems.ru, mccme.ru, архивы)
2. **Строгое форматирование** - LaTeX-редактор оборачивает всю математику в правильный синтаксис для KaTeX

## Архитектура

### Скрипт: [`fetch_original_solutions.py`](../fetch_original_solutions.py)

**Компоненты:**

1. **`fetch_original_solution()`** - поиск оригинального решения
   - Промпт: "Найди ТОЧНОЕ ОФИЦИАЛЬНОЕ решение, ничего не выдумывай"
   - Источники: problems.ru, mccme.ru, ВсОШ, Турнир Городов, ММО
   - Возврат: текст решения или `NOT_FOUND`

2. **`format_solution_latex()`** - форматирование в LaTeX
   - Промпт: "ТОЛЬКО форматирование, НЕ МЕНЯЙ текст автора"
   - Правила: строгий LaTeX для KaTeX
   - Возврат: решение с идеальной разметкой

3. **`main()`** - основной цикл
   - Читает задачи из `OLYMPIADS_DB`
   - Обрабатывает с лимитом (по умолчанию 20)
   - Сохраняет в `olympiads_with_original_solutions.py`

## Системные промпты

### Промпт 1: Поиск оригинала

```
Ты — агрегатор олимпиадной математики с доступом к базе знаний 
problems.ru, mccme.ru и официальным архивам.

КРИТИЧЕСКИ ВАЖНО:
- НИЧЕГО НЕ ВЫДУМЫВАЙ ОТ СЕБЯ
- Если задача имеет классическое решение в 2-3 строчки — выдай именно его
- Ищи решение из официальных источников
- Если не можешь найти точное решение, честно признайся

ВЕРНИ ТОЛЬКО JSON:
{
  "original_solution": "Текст оригинального решения (БЕЗ LaTeX пока)"
}
```

### Промпт 2: LaTeX форматирование

```
Ты — LaTeX-редактор для математических текстов.

ТВОЯ ЗАДАЧА: ТОЛЬКО форматирование математики в строгий LaTeX.
НИ В КОЕМ СЛУЧАЕ не меняй слова, логику или ход решения автора!

ЖЕСТКИЕ ПРАВИЛА ФОРМАТИРОВАНИЯ:
1. Инлайн-формулы: строго в \( ... \)
2. Блочные формулы: строго в \[ ... \]
3. Дроби: ТОЛЬКО \frac{числитель}{знаменатель} (запрещен /)
4. Корни: ТОЛЬКО \sqrt{подкоренное} (с фигурными скобками)
5. Степени/индексы: x^2, p_n, a_{n+1} внутри \( ... \)
6. ВСЕ числа, переменные и формулы в \( ... \)

ПРИМЕРЫ:
- "Пусть \( n = 5 \)" (не "Пусть n = 5")
- "\( x^2 + y^2 = z^2 \)" (не "x² + y² = z²")
- "\( \frac{a+b}{2} \)" (не "(a+b)/2")
- "\( \sqrt{2} \)" (не "√2")
```

## Примеры форматирования

### До форматирования (найденное решение):

```
Пусть скорость течения равна v км/ч, v ≥ 6, v — целое.
Его время: a/11 + c/v
Упростим: b/6 + (b - a)/v < a/11
Попробуем v = 10. Тогда 66(a - b) > 10(11b - 6a)
Возьмём a=89, b=63. Проверим: 66*26 = 1716
```

### После форматирования (идеальный LaTeX):

```
Пусть скорость течения равна \( v \) км/ч, \( v \ge 6 \), \( v \) — целое.
Его время: \( \frac{a}{11} + \frac{c}{v} \)
Упростим: \( \frac{b}{6} + \frac{b - a}{v} < \frac{a}{11} \)
Попробуем \( v = 10 \). Тогда \( 66(a - b) > 10(11b - 6a) \)
Возьмём \( a=89 \), \( b=63 \). Проверим: \( 66 \cdot 26 = 1716 \)
```

## Правила LaTeX форматирования

### ✅ ПРАВИЛЬНО:

| Тип | Правильно | Неправильно |
|-----|-----------|-------------|
| Числа | `\( n = 5 \)` | `n = 5` |
| Степени | `\( x^2 + y^2 \)` | `x² + y²` |
| Дроби | `\( \frac{a+b}{2} \)` | `(a+b)/2` |
| Корни | `\( \sqrt{2} \)` | `√2` |
| Индексы | `\( a_{n+1} \)` | `a_(n+1)` |
| Неравенства | `\( x \ge 5 \)` | `x ≥ 5` |
| Углы | `\( \angle ABC \)` | `∠ABC` |
| Умножение | `\( 2 \cdot 3 \)` | `2*3` |

### Блочные формулы:

```latex
\[
x^2 + y^2 = z^2
\]
```

## Troubleshooting

### Проблема: "NOT_FOUND" для многих задач

**Причина**: Задачи слишком новые или редкие

**Решение**: Это нормально, оставляем старые решения

### Проблема: LaTeX не рендерится на фронтенде

**Причина**: Неправильные разделители

**Решение**: Проверьте, что используются `\(` и `\)`, а не `$`

### Проблема: Скрипт падает с ошибкой JSON

**Причина**: LLM вернул невалидный JSON

**Решение**: Скрипт автоматически пытается извлечь JSON через regex

Скрипт использует [`ai/deepseek_client.py`](../ai/deepseek_client.py):

- **Модель**: `deepseek-chat`
- **Temperature**: 0.2 (поиск), 0.1 (форматирование)
- **Max tokens**: 3000 (поиск), 4000 (форматирование)
- **Retry**: 2 попытки с экспоненциальной задержкой

## Лицензия и источники

Оригинальные решения берутся из открытых источников:
- problems.ru (МЦНМО)
- mccme.ru (Московский центр непрерывного математического образования)
- Официальные архивы ВсОШ
- Архивы Турнира Городов
- Архивы ММО (Московская математическая олимпиада)
