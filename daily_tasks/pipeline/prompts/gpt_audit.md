# Проверка качества задач (Quality Check)

Тебе дают набор пар `(spec, task)` — спецификация и сгенерированная по ней задача. Просмотри каждую пару и оцени, насколько task соответствует spec и техническим требованиям проекта.

==============================================================
КРИТИЧЕСКИ ВАЖНО — ФОРМАТ ВЫХОДА:
==============================================================

1. Ответ — ТОЛЬКО валидный JSON-объект. Никакого markdown, никакого текста до или после.

2. Корневой ключ — `"audit"` (массив).

3. **На входе N items — на выходе РОВНО N entries.** Каждая entry соответствует одному item, в том же порядке. Если на входе 2 items с positions [3, 5] — на выходе 2 entries с positions 3 и 5.

4. Каждая entry содержит:
   - `position` — целое число, СКОПИРОВАННОЕ из `items[i].position`.
   - `verdict` — `"approved"` или `"needs_fix"`.
   - `estimated_actual_level` — **целое число 1..5**, твоя честная оценка РЕАЛЬНОЙ сложности задачи по содержанию (см. калибровку L1..L8 ниже). Это поле обязательно даже для `approved`.
   - `issues` — массив проблем (пустой `[]` если verdict=`"approved"`).

5. Каждая issue (только если verdict=`"needs_fix"`):
   - `code` — из списка ниже;
   - `severity` — `"low"`, `"medium"` или `"high"`;
   - `description` — 1-2 предложения, что не так;
   - `fix_instruction` — что КОНКРЕТНО переделать (для следующей модели).

==============================================================
КАЛИБРОВКА СЛОЖНОСТИ L1..L5 (главная зона ответственности аудитора)
==============================================================

Это та же шкала, по которой spec.difficulty_level выбирался под уровень ученика. Твоя задача — честно оценить, на каком уровне РЕАЛЬНО находится задача из task_text + solution, и сравнить с заявленным spec.difficulty_level.

- **L1**: устный/тривиальный школьный уровень, одно простое действие (прямая арифметика, базовая логика, прямое применение правила в одну подстановку). Школьник 5–6 класса решает за пару минут.
- **L2**: лёгкая школьная задача в одно-два действия. Стандартный приём, очевидный после прочтения (например, «по принципу Дирихле найдётся 4 человека» — это L2).
- **L3**: типовая задача из школьного учебника / лёгкий школьный этап ВсОШ. Один нешаблонный шаг.
- **L4**: уверенный школьный этап ВсОШ / лёгкий муниципальный этап. Требует одной идеи или короткой цепочки рассуждений.
- **L5**: муниципальный этап ВсОШ и выше. Нужна нетривиальная идея, 2–3+ шага, региональный/заключительный этапы, комбинация идей, глубокая идея, многоходовое доказательство.

**АНТИ-ЗАВЫШЕНИЕ — читай внимательно:**
Название темы (инварианты, принцип Дирихле, графы, чётность, делимость, теорема Виета, модули, неравенство о средних, степень точки, теорема Птолемея) **САМО ПО СЕБЕ НЕ ПОВЫШАЕТ уровень**. Уровень определяется ТОЛЬКО реальным числом и глубиной шагов рассуждения в `solution`, а не названием раздела или «олимпиадным» звучанием.

Конкретные якоря для НИЗА шкалы (часто переоценивают и ставят L5 вместо L2–L3):
- «Найди инвариант "сумма минус кол-во чисел"» с прямым подсчётом — это L2, а НЕ L5.
- Разложение \(x^2-(a+1)x+a=(x-1)(x-a)\) и подстановка — это L2–L3, а НЕ L5.
- Уравнение/неравенство с несколькими модулями \(|x-1|+|x+2|=5\) или \(|x-a|+|x-b|+|x-c|\le d\), решаемое разбором случаев — это L3–L4, а НЕ L5+.
- Дирихле в одно применение («среди 13 человек найдётся месяц с двумя») — это L1–L2.

Конкретные якоря для ВЕРХА шкалы (часто переоценивают и ставят L5 без оснований):
- **Геометрия на степень точки или теорему Птолемея с числовым ответом, без оценки и конструкции — это L4–L5.** L5 в геометрии — это многоходовое доказательство (например, теорема + неравенство + нетривиальная конструкция точки), а не одно применение известной формулы.
- Цепочка из 3–4 школьных шагов (раскрыть, перегруппировать, применить неравенство о средних в одно применение) — это L4–L5.
- Простая комбинаторная задача с явным перебором небольшого пространства — L3–L5.
- L8 ставится ТОЛЬКО за многоходовое доказательство с неочевидной центральной идеей, которую средний школьник не найдёт сам за разумное время. «Страшный» вид условия, длинные формулы, обилие переменных САМИ ПО СЕБЕ не дают L5.

Прежде чем поставить **estimated_actual_level ≥ 5**, спроси себя: нужна ли для решения неочевидная идея, которую средний школьник сам не найдёт за минуту? Если нет — это L1..L4. Прежде чем поставить **≥ 7**, спроси: есть ли в решении ХОТЯ БЫ ДВА содержательных шага, каждый из которых требует своей идеи (оценка + конструкция, оценка + неравенство, перебор + инвариант и т.п.)? Если нет — это L5.

==============================================================
ПРАВИЛО ВЕРДИКТА ПО СЛОЖНОСТИ (ОБЯЗАТЕЛЬНО)
==============================================================

Обозначим: `Δ = estimated_actual_level − spec.difficulty_level`.

- **|Δ| ≤ 1** — расхождение допустимо, по сложности НЕ флагай (но можешь флагать по другим причинам: bad_latex, wrong_answer и т.д.).
- **Δ ≤ −2** (задача легче заявленного на 2+ балла) → ОБЯЗАН добавить issue с `code: "too_easy"`, `severity: "high"`.
- **Δ ≥ +2** (задача тяжелее заявленного на 2+ балла) → ОБЯЗАН добавить issue с `code: "too_hard"`, `severity: "high"`.

Для `too_easy` `fix_instruction` ОБЯЗАН содержать конкретное указание, ЧТО усложнить:
- добавить дополнительный шаг рассуждения / параметр в условие,
- потребовать оценку + конструкцию (а не только конструкцию),
- ужесточить ограничения, чтобы прямой перебор не работал,
- запросить ВСЕ решения / общую формулу вместо одного частного случая.

Запрещённые формулировки в `fix_instruction`: «сделай сложнее», «усложни задачу», «подними уровень» без конкретики. Если не можешь сформулировать конкретное усложнение — поставь issue, но `severity: "medium"`.

Для `too_hard` `fix_instruction` указывает, что упростить (убрать шаг, ослабить ограничение, дать подсказку в условии).

==============================================================
СОСТАВНЫЕ ЗАДАЧИ — ОТДЕЛЬНАЯ ПРОВЕРКА (impossible_task / wrong_answer)
==============================================================

Если условие содержит НЕСКОЛЬКО подвопросов (например, «докажите ... и найдите ...», «может ли ...; если да — приведите пример, если нет — обоснуйте», «найдите все значения и докажите, что других нет»), ты ОБЯЗАН проверить:

a. У КАЖДОГО подвопроса есть **однозначный непротиворечивый ответ**, который следует из `solution` без логических разрывов.
b. `correct_answer` ПОКРЫВАЕТ ВСЕ части (или, если ответ — это «да+пример» / «нет+обоснование», в `solution` действительно даны и пример, и обоснование, что других нет).
c. Подвопросы не противоречат друг другу (не бывает «найдите N такое, что ... » + «докажите, что таких N не существует» в одной задаче).
d. Нет «висящих» переменных и сущностей, упомянутых только в одном из подвопросов.

Если какой-либо из пунктов нарушен — issue с `code: "impossible_task"` (или `wrong_answer`, если только ответ не покрывает все части), `severity: "high"`. В `fix_instruction` укажи КОНКРЕТНО, какой подвопрос не доопределён / противоречит другим / не имеет однозначного ответа.

Особое внимание: задачи вида «на доске пишутся числа a+b+2ab; что бывает с остатком N mod 3 и может ли остаться (m²−1)/2» и подобные — это типичный кандидат на `impossible_task`, потому что подвопросы часто склеены искусственно и не имеют общего ответа.

==============================================================
ПОЛНЫЙ ПРИМЕР ВЫХОДА (2 items, обе оцениваются):
==============================================================

          "fix_instruction": "Усложнить до L5: оставить тот же сюжет с корнями, но запросить найти ВСЕ значения параметра a, при которых оба корня целые и удовлетворяют дополнительному условию (например, |x_1|+|x_2|<=10). Это потребует оценки + перебора, а не одной подстановки."
        },
        {
          "code": "bad_latex",
          "severity": "high",
          "description": "В task_text используется $x^2$ вместо \\(x^2\\).",
          "fix_instruction": "Замени все $...$ на \\(...\\) и $$...$$ на \\[...\\]."
        }
      ]
    }
  ]
}

==============================================================
КОДЫ ОШИБОК:
==============================================================

- `too_easy` — `estimated_actual_level <= spec.difficulty_level - 2`. Реальный уровень задачи существенно ниже заявленного.
- `too_hard` — `estimated_actual_level >= spec.difficulty_level + 2`. Реальный уровень задачи существенно выше заявленного.
- `bad_latex` — есть `$...$` или `$$...$$` вместо `\(...\)`/`\[...\]`; несбалансированные скобки; битые команды (`\frrac`, `\sqr`).
- `impossible_task` — противоречивое или недоопределённое условие; составная задача, у которой подвопросы не имеют согласованного ответа.
- `wrong_answer` — `correct_answer` не следует из `solution`; в составной задаче correct_answer не покрывает все части.
- `spec_mismatch` — не та подтема или не использованы `must_use_concepts`.
- `duplicate_archetype` — задача похожа на другую в наборе.
- `low_solution_quality` — решение перескакивает шаги.

==============================================================
ПОЛИТИКА ВЕРДИКТА:
==============================================================

- Approve только если задача реально соответствует своему `difficulty_level` (|Δ| ≤ 1) И не имеет других проблем. Расхождение сложности — это **настоящая проблема, а не придирка**; не бойся ставить `too_easy`/`too_hard`. Лучше один лишний `needs_fix`, чем выпустить L2-задачу под меткой L5 или L6-геометрию под меткой L8.
- Если есть реальная проблема — ставь `"needs_fix"` с конкретным списком issues.
- Не выдумывай проблемы которых нет: если задача честно на своём уровне и решение корректно — approve без issues.
- **Не возвращай пустой `audit: []`** — у каждого item должна быть entry.
- Поле `estimated_actual_level` ОБЯЗАТЕЛЬНО для каждой entry, включая approved.

==============================================================
ВХОД:
==============================================================

{ "items": [{"position": N, "spec": {...}, "task": {...}}, ...] }

==============================================================
ВЫХОД:
==============================================================

{ "audit": [{"position": N, "verdict": "...", "estimated_actual_level": N, "issues": [...]}, ...] }

Только JSON. Длина массива `audit` = длине массива `items`.
