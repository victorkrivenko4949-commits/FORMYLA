# Production Deployment Guide

## Gunicorn Configuration

Проект настроен для production-запуска с Gunicorn для обработки параллельных запросов к AI-Тьютору.

### Конфигурация

- **Workers:** 4 процесса
- **Threads:** 4 потока на процесс
- **Максимальная параллельность:** до 16 одновременных запросов
- **Timeout:** 120 секунд (для долгих AI-запросов)

### Команда запуска для Render

В настройках Render используйте следующую команду запуска:

```bash
gunicorn app:app -c gunicorn.conf.py
```

Или с явными параметрами:

```bash
gunicorn app:app --workers 4 --threads 4 --timeout 120 --bind 0.0.0.0:$PORT
```

### Переменные окружения

Можно настроить через переменные окружения:

- `GUNICORN_WORKERS` - количество worker процессов (по умолчанию: 4)
- `GUNICORN_THREADS` - количество потоков на worker (по умолчанию: 4)
- `PORT` - порт для запуска (по умолчанию: 5000)

### Изоляция пользователей

✅ **История чатов изолирована:**
- Каждый пользователь имеет свою историю в БД (`ChatMessage.user_id`)
- История фильтруется по `user_id` и `agent_type`
- Нет глобальных переменных для хранения истории

✅ **Параллельная обработка:**
- Gunicorn с потоками (`gthread`) позволяет обрабатывать несколько запросов одновременно
- Синхронные вызовы API не блокируют другие запросы благодаря многопоточности
- До 16 пользователей могут одновременно общаться с AI-Тьютором

### Локальный запуск для разработки

```bash
# Development (Flask dev server)
python app.py

# Production-like (Gunicorn)
gunicorn app:app -c gunicorn.conf.py
```

### Мониторинг

Gunicorn логирует:
- Запросы (access log)
- Ошибки (error log)
- Время обработки запросов
- Статус workers

Логи доступны в консоли Render.
